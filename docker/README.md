# Docker Configurations

Docker configurations for building, testing, and deploying the NEXT-100 DAQ system.

## Overview

This directory contains Docker-related files for:
- **Base Image**: HDF5, Blosc, and Go toolchain
- **Build Image**: Compiled binaries for deployment
- **Testing**: Integration test infrastructure
- **E2E Testing**: Full system simulation with Docker Compose

## Directory Structure

```

├── data/                    # Persistent data (git-ignored)

│       └── next100/         # Full NEXT-100 (7 LDC + 7 GDC)

    └── docker-compose.yml   # Test dependencies
```

## Base Image (Dockerfile.base)

### Purpose

Provides all dependencies for building and running the DAQ system:
- HDF5 1.14+ with C++ bindings
- Blosc compression library
- Go 1.24 toolchain
- Build tools (gcc, make, etc.)

### Build

```bash
# Build base image (one-time, ~10 minutes)
task e2e:build-base

# Or manually
docker build -f docker/Dockerfile.base -t duck-backend-test-base:latest .
```

### Image Contents

```dockerfile
FROM rockylinux:9

# HDF5 with Blosc
RUN cd /tmp && \
    curl -LO https://github.com/Blosc/c-blosc2/archive/refs/tags/v2.15.1.tar.gz && \
    # ... build blosc2 ...

RUN cd /tmp && \
    curl -LO https://github.com/HDFGroup/hdf5/archive/refs/tags/hdf5-1_14_5.tar.gz && \
    # ... build HDF5 with blosc2 ...

# Go 1.24
RUN curl -LO https://go.dev/dl/go1.24.4.linux-amd64.tar.gz && \
    tar -C /usr/local -xzf go1.24.4.linux-amd64.tar.gz

ENV PATH="/usr/local/go/bin:${PATH}"
ENV LD_LIBRARY_PATH="/usr/local/hdf5/lib:/usr/local/hdf5-blosc/lib"
```

### Size

- **Base image**: ~2 GB
- **Build time**: ~10 minutes
- **Layers**: ~15

## Build Image (Dockerfile.build)

### Purpose

Compiles Go binaries in a consistent environment with HDF5/Blosc dependencies.

### Build

```bash
# Build with compiled binaries
task e2e:build

# Or manually
docker build -f docker/Dockerfile.build -t duck-e2e:latest .
```

### Usage

```bash
# Build API binary
docker run --rm -v $(pwd):/src duck-e2e go build -o bin/api ./api

# Build GDC binary
docker run --rm -v $(pwd):/src duck-e2e \
    CGO_ENABLED=1 \
    CGO_LDFLAGS="-L/usr/local/hdf5/lib -L/usr/local/hdf5-blosc/lib" \
    go build -o bin/gdcRPC ./gdcRPC
```

## E2E Testing (e2e/)

### Purpose

Full system simulation with Docker Compose, including:
- MySQL database
- Centrifuge messaging server
- API server
- LDCs and GDCs
- Device simulators
- GUI (in dev mode)

### Quick Start

```bash
# Build and start full system
task e2e:up:dev

# Services available:
# - GUI: http://localhost:5173 (hot reload)
# - API: http://localhost:1323
# - Centrifugo: http://localhost:8000
# - MySQL: localhost:3306
```

### Configuration Files

#### docker-compose.yml

Base compose file with:
- MySQL service
- Centrifuge service
- Network configuration
- Volume definitions

#### setups/standard/docker-compose.gen.yml

Standard test setup:
- 2 LDCs (ldc1, ldc2)
- 2 GDCs (gdc1, gdc2)
- 4 test devices (2 per LDC)
- Generated by `e2e:gen` task

#### setups/next100/docker-compose.gen-next100.yml

Full NEXT-100 simulation:
- 7 LDCs (ldc1next - ldc7next)
- 7 GDCs (gdc1next - gdc7next)
- 28 device simulators (4 per LDC)
- Real data replay
- Generated by `e2e:gen:next100` task

### Environment Variables

Copy `.env.example` to `.env`:

```bash
# MySQL
MYSQL_ROOT_PASSWORD=duck
MYSQL_DATABASE=duck
MYSQL_USER=duck
MYSQL_PASSWORD=duck

# Centrifugo
CENTRIFUGO_API_KEY=your-api-key
CENTRIFUGO_TOKEN_HMAC_KEY=your-hmac-key

# API
API_PORT=1323
```

### Commands

```bash
# Start standard setup
task e2e:up

# Start with GUI dev server
task e2e:up:dev

# Start NEXT-100 simulation
task e2e:up:next100:dev

# View logs
task e2e:logs

# Stop everything
task e2e:down

# Recompile without resetting database
task e2e:recompile
```

### Data Persistence

Data is stored in `docker/data/` (git-ignored):
- MySQL data: `docker/data/mysql/`
- GDC output: `docker/data/gdc*/`

To reset:
```bash
task e2e:down  # Removes volumes
```

## Performance Considerations

### Image Sizes

- **Base image**: ~2 GB

```yaml
      resources:
        limits:
          cpus: '2'
          memory: 1G
```

### Network Performance

- **Internal network**: Bridge driver
- **Host access**: `host.docker.internal`
- **Port mapping**: As configured in compose files

## Troubleshooting

### Base Image Build Fails

```bash
# Check available disk space
df -h

# Clear Docker cache
docker system prune -a

# Rebuild without cache
docker build --no-cache -f docker/Dockerfile.base -t duck-backend-test-base .
```

### MySQL Connection Refused

```bash
# Wait for MySQL to be ready (30s)
docker compose -f docker/e2e/docker-compose.yml logs mysql

# Check MySQL is running
docker compose -f docker/e2e/docker-compose.yml ps mysql
```

### HDF5 Library Not Found

```bash
# Verify HDF5 installation in container
docker run --rm duck-backend-test-base ls -la /usr/local/hdf5/lib/

# Check LD_LIBRARY_PATH
docker run --rm duck-backend-test-base env | grep LD_LIBRARY_PATH
```

### Port Already in Use

```bash
# Find process using port
lsof -i :1323

# Kill process
kill -9 <PID>

# Or change port in .env
API_PORT=1324
```

## Best Practices

1. **Layer Caching**: Order Dockerfile instructions from least to most frequently changing
2. **Multi-stage Builds**: Use build stages to reduce final image size
3. **Volume Management**: Use named volumes for persistence, bind mounts for development
4. **Resource Limits**: Set CPU/memory limits in production
5. **Health Checks**: Add health checks for critical services
6. **Security**: Don't run containers as root in production
